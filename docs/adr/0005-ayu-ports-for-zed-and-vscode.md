# Ayu's Zed and VS Code themes are ports

Ayu Dark Contrast is meant to look like ayu with only the background, text, and greys changed. The colours alone don't get there: every family shares `build.py`'s mapping of syntax roles to scopes and captures, which was written for Geist, so ayu's colours landed on the wrong text. In Zed, Markdown links came out cyan where ayu has orange italic link text and green URLs.

So in Zed and VS Code, where ayu has a theme of its own (Zed's built-in Ayu Dark and ayu's VS Code extension, both MIT), the palette takes that theme as a port. Its recolour table swaps the backgrounds, text, and greys, and any colour the contrast gate fails: the find fills, Zed's selection and hint text, two error reds, and Zed's dark bright-terminal colours. Where one colour serves two roles, such as placeholder text and a button's hover fill, a per-key table sets the key the recolour table can't reach. It also adds ADR 0002's find borders, which ayu doesn't set. The other apps either have no popular ayu theme or theme few roles, so they keep the generated mapping.

The ports are copies under `palettes/ayu/ports/`, so ayu's later changes reach them only when someone copies them again, and each port's licence ships next to its output. ADR 0003 has the build stop on any surface behind syntax text that falls short; for a port, the gate checks every syntax, token, and semantic colour against the editor background, current line, selection, and find fills, and every terminal colour but black against the terminal background. Other surfaces ayu draws behind code, such as word highlights, keep ayu's colours unchecked.
